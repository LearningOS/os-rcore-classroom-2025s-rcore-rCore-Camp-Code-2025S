# 总结
sys_trace系统调用实现逻辑如下：
根据trace_request进行匹配，如果为0，则返回内存地址为_id处的值，如果为1，则将_data的值写入内存地址_id处，如果为2，则获取当前任务中系统调用号为_id的系统调用的次数，其他则返回-1.
trace_request为2时的实现方式如下：定义一个struct SyscallCounter，记录syscall_id和syscall_count，初始化为0，在TCB中定义一个数组，为每个syscall_id保存一个SyscallCounter，每次执行syscall时，首先执行一次add counter的操作，并提供返回counter的接口。
# 问答题
1. sbi版本：RustSBI version 0.3.0-alpha.2, adapting to RISC-V SBI v1.0.0。出错行为如下：
   - ch2b_bad_address：访问0地址内存并尝试修改，内存地址0是受到保护的内存地址，不允许用户程序修改，因此触发了PageFault
   - ch2b_bad_instructions：直接执行"sret"汇编指令，可能会造成特权级违规，因此会触发非法指令异常
   - ch2b_bad_register：sstatus是一个特权寄存器，属于监管模式的控制状态寄存器，用户态直接访问会触发非法指令异常
2. 1. 刚进入_restore时，由于mv a0, sp指令，此时sp的值是内核栈上已分配的TrapContext结构体的起始地址。_restore两种使用场景分别是：
      - 第一次加载任务时，将任务上下文信息加载进内核
      - 切换任务时，切换任务上下文
   2. 分别处理了sstatus，sepc，sscratch寄存器， sstatus保存了Trap发生之前CPU的特权级，sepc记录 Trap 发生之前执行的最后一条指令的地址，sscratch记录了用户栈指针，分别用于恢复用户态特权级，恢复指令执行，恢复用户栈
   3. 跳过x2是因为x2寄存器进行了单独处理，因此没有保存，跳过x4是因为它没有被用到，所以也没有被保存
   4. L60交换sp和sscratch，此时sp恢复为用户栈，sscratch重新指向内核栈
   5. 状态切换指令：sret，执行该指令之后，程序返回用户态。_restore中csrw sstatus, t0指令恢复了CPU的特权级，而在_alltraps中保存的特权级是用户态，所以执行sret之后会进入用户态
   6. csrrw sp, sscratch, sp互换用户栈和内核栈的栈指针，此时sp指向内核栈，sscratch保存用户栈指针
   7. 从U态进入S态是通过ecall指令发生的
