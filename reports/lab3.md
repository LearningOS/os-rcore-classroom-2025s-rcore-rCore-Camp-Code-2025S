# 问答作业

1. 实际情况不会轮到p1执行，而是p2会再次被调度，原因如下：

   - **初始状态**：p1.stride = 255（8位无符号整数最大值附近），p2.stride = 250。
   - **p2执行后**：p2.stride = 250 + 10（pass）= **260**。由于使用8位无符号整数存储，260会溢出为**4**（即260 mod 256 = 4）。
   - **新的比较**：此时p1.stride = 255，p2.stride = 4。调度器选择`stride`更小的进程，即**p2**会被再次选中
   - **核心机制：**Stride调度算法通过维护每个进程的`stride`值（调度权）和`pass`值（步长）来实现优先级调度：
     - 每次调度时选择当前`stride`值最小的进程执行。
     - 进程执行后，其`stride`会累加自身的`pass`值（即`stride += pass`）。
     - 若两个进程优先级相同（即`pass`值相等），理论上应交替执行，保证公平性。

2. 由定义 pass = BigStride / priority，当优先级 ≥ 2 时，步长 pass 的最大值为 BigStride/2（对应优先级为 2 的情况）。这意味着任何进程单次执行后，其 stride 的增量不会超过 BigStride/2。每次调度选择当前 stride 最小的进程执行，执行后该进程的 stride 会增加 pass。由于所有进程的 pass 均 ≤ BigStride/2，在极端情况下（如两个进程交替执行），最大差距最多为 BigStride/2。例如：若进程 A 的 stride 达到最大值，进程 B 的 stride 被调度后增加 pass，此时差距仍会被限制在 BigStride/2 以内。

   impl PartialOrd for Stride {
       fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
           let a = self.0;
           let b = other.0;
           let diff = a.wrapping_sub(b) as i64;
   
           // 关键逻辑：判断差值是否超过 BigStride/2（阈值=127）
           if diff.abs() > (BIG_STRIDE / 2) as i64 {
               // 溢出回绕场景，反转比较结果
               Some(diff.cmp(&0).reverse())
           } else {
               // 正常比较
               Some(a.cmp(&b))
           }
       }
   }
