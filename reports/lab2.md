# 问答题

1. 页表项的组成如下：[63:54]为保留位，[53:10]为物理页号，分成三级，[9:0]为标志位，标志位的作用如下：
   - V，通常表示有效位（Valid bit），用于指示该页表项是否有效。如果 V=1，页表项有效；V=0，页表项无效，访问可能会引发页错误
   - R/W/X 分别控制索引到这个页表项的对应虚拟页面是否允许读/写/取指
   - U 控制索引到这个页表项的对应虚拟页面是否在 CPU 处于 U 特权级的情况下是否被允许访问
   - G，全局位（Global bit），在 TLB（转换 Lookaside 缓冲区）中是否全局有效，用于减少 TLB 刷新
   - A(Accessed) 记录自从页表项上的这一位被清零之后，页表项的对应虚拟页面是否被访问过
   - D(Dirty) 则记录自从页表项上的这一位被清零之后，页表项的对应虚拟页表是否被修改过
   - RSW，保留位（Reserved for system use），系统保留，可能用于未来扩展或特定系统功能
2. 1. 由缺页引发异常可能包括以下几种
      - 页面未加载：进程访问的页面存在于虚拟地址空间但未加载到物理内存（页表项存在位为无效）
      - 权限问题：例如尝试写入只读页面、用户态访问内核态页面等。
      - 保留位冲突：页表项中的保留位被错误置位
      - 无效地址：访问未分配的虚拟地址（操作系统可能判定为非法，终止进程）
   2. 发生缺页时的重要寄存器及其值
      - scause（异常原因寄存器），记录触发异常的原因。
        - 最高位（Bit 63） ：0表示异常（非中断），1表示中断
        - 低63位：异常代码，具体值如下：
          - 12：指令缺页（Instruction Page Fault）
          - 13：加载缺页（Load Page Fault）
          - 15：存储缺页（Store/AMO Page Fault）
      - stval（异常值寄存器），保存触发缺页的虚拟地址
        - 值：用户程序尝试访问的虚拟地址，供操作系统处理缺页时使用。
      - sepc（异常程序计数器），保存触发异常的指令地址，异常处理完成后从此地址恢复执行
        - 值：触发缺页的指令的PC（Program Counter）值。
      - sstatus（状态寄存器），包含当前特权模式（如用户态或监管态）和中断使能状态
        - 关键位：
          - SPP（Bit 8） ：异常发生前的特权模式（0=用户态，1=监管态）。
          - SPIE（Bit 5） ：异常发生前的中断使能状态。
   3. Lazy 策略通过 按需分配物理资源，平衡了性能、内存利用率和用户体验：
      - 程序启动优化（减少延迟）
      - 稀疏内存访问（节省物理内存）
      - 多进程共享资源（如动态库、COW）
      - 动态内存需求（如堆扩展、稀疏数据结构） 
   4. SV39 采用三级页表（L2、L1、L0），每个页表页大小为 4KB，包含 512 个页表项（PTE）。每个 L2 页表项映射 1GB 虚拟空间，每个 L1 页表项映射 2MB，每个 L0页表项映射 4KB。10G 虚拟空间需要：
      - 1 个 L2 页表页（含 10 个有效项）。
      - 10 个 L1 页表页（每个对应 1GB，各含 512 项）。
      - 5120 个 L0 页表页（每个 L1 页表项对应一个 L0 页表页，共 10 * 512 = 5120）。
      - 总页表页数：1（L2） + 10（L1） + 5120（L0） = 5131 页。总内存占用：5131 * 4KB ≈ 20.5MB（数量级为 10MB 级）。
   5. Lazy 策略实现：
      - 延迟分配：在 mmap 时仅记录虚拟地址范围（VMA），不立即分配页表或物理页。
      - 缺页处理：
         - 访问未映射的虚拟地址触发缺页异常。
         - 检查地址合法性后，按需逐级分配中间页表页（L2 → L1 → L0）和物理页。
         - 更新页表项，建立虚拟地址到物理页的映射。
   6. 当内存页面被 swap 到磁盘上导致页面失效时，这种失效在页表项（PTE）上的表现主要体现在以下几点：
      - 有效位（Valid Bit）置零：页表项中的有效位被清零，表示该页面当前不在物理内存中，而是被换到了磁盘上。
      - 记录磁盘位置信息：页表项中可能记录该页面在磁盘上的位置信息，以便在需要时能够快速加载回来。
      - 维护其他状态信息：页表项中可能包含其他状态信息，如访问权限、修改位（Dirty Bit）和访问位（Accessed Bit）等，这些信息在页面被 swap 后仍然需要被维护，以便在页面被重新加载回内存时，能够正确地恢复其状态。
3. 1. 在单页表设计中，用户线程和内核线程共用同一张页表。更换页表通常发生在上下文切换时，即当系统从一个进程切换到另一个进程时，需要更新页表寄存器（Page Table Register，简称 PTR）指向新的页表。这是因为每个进程都有自己的虚拟地址空间，需要对应的页表来映射物理内存。更换页表的步骤如下：
      - 保存当前页表的上下文：在切换进程之前，需要保存当前页表的状态，包括页表寄存器的值和其他相关寄存器。
      - 加载新的页表：根据目标进程的页表地址，更新页表寄存器，使得 CPU 使用新的页表进行地址转换。
      - 处理缓存和TLB：由于页表更换后，Translation Lookaside Buffer（TLB）中的条目可能不再有效，需要进行刷新或部分刷新，以确保地址转换的正确性。
   2. 在单页表设计中，用户态和内核态共享同一张页表，但内核页面只能在内核态下访问。这通常通过权限控制和地址空间的隔离来实现。
      - 页表项的权限位：页表项中包含权限位（如读、写、执行权限），在内核页面的页表项中，设置权限位使得用户态无法访问。例如，内核页面可能只允许内核态读写，而用户态无法访问。
      - 地址空间的隔离：虽然用户态和内核态共享同一张页表，但内核页面的虚拟地址范围通常与用户页面分开，用户态无法通过正常的虚拟地址访问到内核页面。
      - 异常处理：当用户态尝试访问内核页面时，硬件会检测到权限违规，触发异常（如 General Protection Exception），操作系统在异常处理中终止该用户的访问请求。
   3. 内存占用低：只维护一张页表，减少了内存的使用量。上下文切换快：由于页表数量少，上下文切换时需要处理的页表信息较少，切换速度更快。实现简单：单页表设计相对简单，开发和维护成本较低.
   4. 在双页表设计中，用户线程和内核线程使用不同的页表。页表的更换主要发生在以下几种情况：
      - 用户态与内核态切换：当系统从用户态切换到内核态（如中断、系统调用）时，需要更换页表，使得 CPU 使用内核的页表进行地址转换。
      - 进程切换：在多任务操作系统中，当从一个进程切换到另一个进程时，需要更换用户态的页表，而内核态的页表通常保持不变。
      - 内存管理操作：在进行内存分配、释放等操作时，可能需要更新页表，但通常不需要更换整个页表，而是更新特定的页表项。    
      - 切换页表的时机：
        - 进程切换时：当从一个进程切换到另一个进程时，需要加载目标进程的页表，以确保地址转换正确。
        - 内核态与用户态切换时：虽然单页表设计中用户态和内核态共享页表，但在切换到内核态时，可能需要重新加载页表寄存器，以确保内核页面的访问权限正确。
        - 内存分配或释放时：当需要调整页表以反映内存的变化时，可能需要重新加载页表寄存器。
